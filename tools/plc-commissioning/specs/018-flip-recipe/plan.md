# 实现计划

## 2026-10-08实施承接

以下保留018历史实施计划；新增清零机制由[020阶段A计划](../../../../specs/020-real-device-commissioning/plan.md)承接，已实现及离线验证、未发布，见[实际记录](../../../../specs/020-real-device-commissioning/validation.md)。App纯采集与worker/recipe推进分开，等待清零跨轮次释放锁；轴、XY和reuse最终复核统一使用新鲜证据。放回末端确认两项反馈0；分拣最终安全位完成后才清父命令。清零计入现动作/末段期限，失败不重发。旧“防递归”意图必须由实际采集/推进隔离证明，不能在锁内等下一轮采样。其他历史设计及验证不据此改写。

新增recipe.py独立状态机、recipe.default.json、/recipe页面与SVG路径。复用App的串行锁、write_checked、begin_axis和本次反馈判定。推进在poll后进行且防递归；连接/打开界面不启动配方。

每个跨位置先移各Z到现场明确的安全高度，未配置则等待操作员确认。XY按X后Y逐轴执行，路径图按实际命令顺序绘制折线路径。相同已完成定位可复用但不伪造新运动。型号/抓手缺失等待填写，不阻挡监视。

使用独立回环服务测试完整OK/NG/Pending流程、旧完成拒绝、暂停/断线、相机模拟标记、无R/E/旋转命令、翻面Z隔离、方向字序、页面参数/路径/信号变化。现场仅只读上线，运动测试由操作员启动。

最终执行模式：用户确认所有安全高度为2且不要逐步确认，故中间PLC步骤自动等待反馈推进；模拟相机依据显式预设自动产生并标记模拟结果。仅人工上料/取盘需确认；真实相机未集成，可选操作员现场结果确认。翻面完成使Z位置缓存失效，下一次跨点重新退Z，不凭旧Z命令推断安全。

验证：31项回环单元检查、14步完整12秒延时浏览器流程、85项旧联调界面浏览器回归通过。硬件本配方尚未执行。现场配置保留独立CDAB读/写与物理PLC网卡绑定，新增全部五轴±0.1、三个Z安全2。共享仅工作目录Start-PLC.ps1及三个.cmd启动入口更新为1.1.0；正式软件/主工程0项。完整包自包含Python Windows x64，无SDK依赖。


## 2026-10-07 用户修订配方到位判定（1.1.4）
用户明确要求到位状态1即可推进，结合已确认的±0.1实际位置容差：配方轴在目标写入和启动写入均应答、读回相符后，以启动后的新鲜轮询到位=1且实际坐标误差≤0.1作为完成条件，不再强制观察1→0→1。按原流程清启动并读回0后继续。日志明确标注未观察运动跳变，不能伪造运动证据；手工单轴原判定及翻面/放料真实反馈规则保持。超时、无效反馈、故障、断线和坐标不符仍不通过。不自动重跑旧失败盘、不发送现场测试运动。

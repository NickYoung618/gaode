二、如何放到中控机

1. 下载 Gaode-Migration-20261006.zip 及同名 .sha256.txt。PowerShell 执行：
   Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\Downloads\Gaode-Migration-20261006.zip'
   对照摘要后解压到一个新的短路径，例如 D:\GaodeTransfer。不要直接覆盖现场已有项目。
2. 解压根目录先双击 Verify.cmd；它调用 Python 检查逐文件摘要、Git 提交、标签、远程地址和离线 bundle，任何失败都会显示并停留。首次校验请在移动文件前执行。
3. 包中 E-drive 代表推荐恢复到 E: 的目录树：
   E-drive\dzk\gaode-1       → E:\dzk\gaode-1（完整源码，务必包含隐藏 .git/.agents/.specify）
   E-drive\dzk\gaode         → E:\dzk\gaode（原型.zip、软件开发SDK.zip，保持原件不变）
   tools                    → 任意独立联调工具目录，分别解压，不覆盖原现场配置
   evidence                 → development-evidence.zip 保存完整选定历史证据，路径对应见 relocation-map.json
   data-snapshots            → 一致性数据库备份，仅保留待核对，不自动安装到业务目录
4. 如果中控机已有 E:\dzk\gaode-1 或现场 Codex 正在修改它，请保留它，先将本包项目放到新目录，交给 Codex 按基线比较合并。不要整目录覆盖正在开发的代码、现场 site.json 或数据库。没有 E: 也可以先用其他盘；少数历史验证脚本含 E:/C: 绝对路径，按 relocation-map 和实际脚本单独调整配置，不全局改写原始证据。
5. 源码 artifacts 中直接保留简短交接说明和索引；深层测试记录、016 集成/恢复资料及 C: 来源证据在 evidence/development-evidence.zip，附逐文件摘要。此内层 ZIP 不必全部解压；需要某次证据时，按 relocation-map 定向展开到短路径，避免 Windows 长路径限制。repo-artifacts 下内容对应主工程 artifacts，dzk-delivery 下内容对应 E:\dzk-delivery。运行数据快照在包外层 data-snapshots，不把源机 PID、进程锁、浏览器登录状态或 Codex 账号状态恢复成运行状态。

六、日常保存与回传

在中控机项目目录操作（首次开发，分支名若已存在则直接切换）：
   git switch -c field/integration
   git status --short
   git diff
   git add <本次修改的明确文件或目录>
   git diff --cached --stat
   git commit -m "记录本次现场接入内容与验证结果"
   git push -u origin field/integration
上述 <...> 是占位，替换成实际文件，不要原样执行。中控机推送需要用自己的 GitHub 登录（例如已有 gh 时 gh auth login），不要把 token 写入脚本、远程地址或聊天。拉取公开仓库本身不需要写权限。
一个阶段验收通过后，例如：git tag field-plc-pass-20261007，再 git push origin field-plc-pass-20261007。标签名按实际日期和已通过范围命名，不覆盖已发布标签。
源码、规格、地址模板纳入 Git；site.json、现场 profile、数据库、图像和日志另行保存并随反馈包交付。不要 git add -f 强行提交凭据或现场数据。现场配置建议放项目 artifacts 下的独立目录，以免误提交到公开仓库。

七、如何回退（保留现有工作）

回退前停止相关软件对设备的控制，保存现场配置，并对已停止的数据库或用 SQLite backup API 作一致性备份。先提交当前代码或保留现有工作目录；不要用 reset --hard、clean -fd 或覆盖目录丢掉未提交改动。
推荐另开一份旧版本目录：
   git fetch origin --tags
   git worktree add -b rollback/migration-20261006-r1 E:/dzk/gaode-rollback-20261006 migration-20261006-r1
   git -C E:/dzk/gaode-rollback-20261006 log -1 --oneline
标签已随包带来；断网时省略 fetch，也可执行 worktree。目录与分支已经存在时选一个新的名称。原目录不受影响；在旧版本目录按它自身的依赖、配置及数据版本重新构建和验证，再决定切换运行目录。不能同时运行两套程序写同一 PLC。
若只需撤销一个错误提交，可在开发分支使用 git revert <提交号>，解决冲突并验证后推送。这会生成新的撤销提交并保留历史，不强推公共分支。
如果 .git 丢失，可从包根的 gaode-repository.bundle 离线恢复：
   git clone gaode-repository.bundle E:/dzk/gaode-recovered
   git -C E:/dzk/gaode-recovered remote set-url origin https://github.com/NickYoung618/gaode.git
也可 git clone https://github.com/NickYoung618/gaode.git 到新目录；另保留本包的 SDK、资料和数据快照。
Git 只回退入库文件，不回退 PLC 程序、数据库、配方内容、相机固件和现场配置。当前存储 s01-store/3、配方 recipe-definition/5；历史程序不保证能打开升级后的库，必须使用匹配的数据备份或受控迁移。data-snapshots 仅是源机测试数据的一致快照，不能直接覆盖现场生产库。

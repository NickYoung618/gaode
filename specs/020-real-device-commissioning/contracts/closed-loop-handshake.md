# HC-020：完整闭环后的双方清零契约

版本：020-stage-a/1，2026-10-08。阶段A已实现及离线验证，见[validation](../validation.md)；未发布/真机验收。适用FR-005–008、010–011、015–017。依据为用户已确认PLC-Q1/Q1、PC.xls/PLC.xls及020 spec；不增PLC信号，不改现场原件。

## HC-01 所有权与完整闭环边界

PC仅清自己的请求，PLC独立清反馈。地址均十进制MB字节地址，编码/换算只在通信适配层。下表“全0集合”必须全部新鲜读取，不能只检查反馈的一项或PC写应答。

| 资源 | 物理完成与允许清请求的边界 | PC清请求 | 须确认全0集合 |
| --- | --- | --- | --- |
| X | 本次到位及实测在容差内 | 2001 | 2001、6040 |
| Y | 同上 | 2002 | 2002、6042 |
| 检测Z | 同上 | 2003 | 2003、6044 |
| 扫码Z | 同上 | 2004 | 2004、6046 |
| 抓取Z | 同上 | 2005 | 2005、6048 |
| R | 本次到位及实角满足原角度合同 | 2000 | 2000、6060 |
| 翻面/放回 | 翻面完成为中间态；放回完成2含PLC内部翻面Z安全完成后才清 | 2014 | 2014、6050、6052 |
| 公共取放/分拣 | 取料→必要保存/提交→转运→放料完成→最终安全位子轴闭环完成 | 2016 | 2016、6054 |

2018/6062抓手选择保持；2006/6015就绪、2011/6038心跳不在此清零集合。2007/2009系统重启/复位及2008软停不是本契约清请求。翻面不新增抓手选择；不为OK原槽路线添加NG分拣或R。

工具手工轴的既有诊断差异：原路径按本次Moving→Arrived确认运动，坐标误差验收可未配置或未通过，不因本阶段暗改成配方定位规则；其正常清请求边界沿原运动完成判据，实际位置/误差如实报告。未取得有效坐标验收的完成记录不能直接建立定位复用资格；有配置须匹配原容差，无配置仅有限坐标精确匹配可作复用资格。正式及工具配方仍须各自既定定位验收。此差异不豁免任何入口的双方清零确认。

## HC-02 分阶段解释反馈

轴状态0仅在本次启动派发后的有效采样中可作为原合同的Moving证据；清零阶段0或派发前0不证明新运动。轴1为到位，2为超时。正式实际运动保留派发后Moving→Arrived及实测位置判据，不额外要求派发前反馈必须1；否则正常清0后的下一轮将不能开始。

翻面/放回0空闲、1执行、2完成、3失败；Sort 0空闲、1取料完成、2放料完成、3失败。Flip命令1→2、Sort命令1→2是同一父周期中间阶段，不能插入父命令0或要求其反馈先全0。轴子周期清自己的启动不清父命令。

正式与工具的实际运动判据必要差异见TC-03，不扩大旧工具放宽范围。

## HC-03 清写与采样证明

1. 先核实际完成/实测及适用安全位，保存其身份。仅对本周期实际发出的请求清0一次；未发启动的复用轴无需清写。
2. 用实际通信收据记录最后一个相关清写应答完成水位。写应答或PC读回0不是PLC已清零证明。
3. 经原采样路径发起所需请求/反馈读。每字段读取发起水位须不早于上述写完成水位，同一连接及当前周期，质量有效，在消费时满足既有新鲜度。不同块可分读，但不得拼入旧缓存。
4. 全0、仍未取消/过期/失效，生成本周期ClearanceProof。相关资源才Closed；在此前禁止下一次相关请求，包括手工、配方和通用写入口。
5. 再次实际派发前仍核当前新鲜请求/反馈及安全状态。清零证明不是永久免检证；出现意外非零或状态失效即阻断并失效对应复用记录。

正式实现沿PlcExchangeClock、SignalValues.Stamps、WaitGroupAsync与同一Pump。轴B完整读取Starts+Axes，避免X活动组导致缺字段/旧字段；R/T/U增加有限清零读用途，U须同时读FlipSorting/FlipStatus/FlipUnloadStatus，不新增采样器。

## HC-04 同坐标复用

每个被复用轴必须同时满足：本连接已有实际到位及双方清零记录；自记录建立后无相关移动/复位/失效；本次新鲜请求0、反馈0、有效设备状态及实测在本次目标容差内。输出PositionReused，不写目标/启动，不等Moving，不伪造新动作完成。

混合组只启动需要移动的轴；全同坐标可完成上层定位，但两类均最终复核所有相关轴。Y/检测Z没有特别豁免，不扩大容差。正式用已有经验证容差；工具配方用冻结配置容差，手工无容差时只允许有限坐标精确相等复用。

首次连接、重连、已观察复位、未知/安全失效、漂移、非法位置、其他路径可能移动该轴均不能借旧记录。无记录只禁止“不启动沿用”，不新增首次正常移动前必须有旧动作的条件，也不自动试走/回零。已有安全准入不满足时维持阻断；Q2的恢复说明不在本阶段猜定。

## HC-05 截止与错误

清零计入当前阶段原动作绝对期限及适用phase剩余预算，不重新起算；原I/O timeout仍仅约束每笔通信。Flip与PutBack原为不同窗口，父关联跨阶段保留，最终清零占PutBack原窗口，不能用已结束的Flip截止限制合法后续，也不新造贯穿父周期的期限。工具按plan明确的原actionTimeout末段截止。等待中保持原心跳、安全监视和取消通路。

| 情况 | 必须行为 |
| --- | --- |
| 反馈延迟非0 | AwaitingClear，保留所有权，无后继相关请求，不反复清写 |
| 截止仍非0 | 明确“动作已完成，但PLC反馈未清零，已阻止后续动作”及资源/原值/期限；整体结果不成功 |
| 反馈过期、质量无效、读失败、连接变化 | 停止推进，记录相应原因，沿原失败/未知保持，不能以最后缓存0解锁 |
| 清写结果未知 | 不视为已撤请求，不自动重写或重发动作用以探测 |
| 超时后迟到全0 | 仅记录诊断，不自动恢复、Closed或重发；恢复遵循现有核对义务 |

实现可使用既有错误类型/终态，增加具体reason/诊断；不把已经证实的物理完成改成未发生，也不将清零失败报成功。

## HC-06 准入及人工操作

资源守卫覆盖所有相关写路径。新父周期不得接受残留Placed/FlipCompleted作为空闲；同父周期放料仍正确接受Picked。物理持件与未知义务优先于后续请求。

人工清请求保留原显式入口和互斥规则，但也须记录请求清写与PLC反馈清零的区别；它不是物理完成/同坐标资格/未知恢复证明。人工清零未获实际反馈时，不能显示“已清零”。通用写不能绕过资源守卫；详见TC-02。

## HC-07 事实、保存与业务端口

保持现IPlcStageActionPort及业务位置/完成类型，不输出MB或raw code。内部实际派发轴保留到位PositionObservation，完成发射和Stage消费它，不清零后再Observe拼成“到位事实”。复用轴则以历史闭环作资格，用本次新鲜复核形成关联当前Action的定位证据并更新原reachedPositions，满足IsCorrelated/RequireKnownPosition和后续采集；不能直接返回旧动作证据。旋转、翻面/放回沿现保存的完成样本身份。清零证明以现诊断关联，DB/schema不变。

取料完成先走原IPickCommitPort可靠提交再转运；清零不得抢在提交/放料/安全位之前。业务完成及释放控制权须同时满足原必要保存与适用清零；物理动作完成不等于整个业务阶段完成。

翻面/放回Acquisition路径保存发生在底层执行返回之后，当前阶段所有权须延续至保存成功；不得由底层finally提前释放auxiliary开放新请求。保存失败进入原未知保持；翻面中间成功仅开放已关联的父周期后续动作。

## HC-08 替身与来源

VirtualPlc及工具模拟器自行产生清反馈，支持离线延迟/保持用于最小测试。轴/R及Sort补齐清反馈；Flip保持末端清两反馈。VirtualPlc分拣原持续反馈1前提改为自身已完成、停稳且位置有效的内部事实，不能删掉位置保护或共享PC记录。复位使新引入事实失效，不把模拟器规则当现场复位解释。

本契约不解除017 Real定义/安全阻断，不导入测试机械坐标到真机。后续现场配置仍按spec的XLS哈希、编码证据及用户安全值核对。

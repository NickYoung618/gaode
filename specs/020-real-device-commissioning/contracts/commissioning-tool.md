# TC-020：联调工具可观察行为与同步契约

版本：020-stage-a/1，2026-10-08。适用现`tools/plc-commissioning`；已实现及离线验证，见[validation](../validation.md)，未发布。与[HC契约](closed-loop-handshake.md)共同替代旧“写启动0成功即cleared”的规则，不新建HTTP端点，不更改页面。

## TC-01 现状态兼容

保留`/api/state`、`/api/axis`、`/api/clear`、`/api/write`及既有recipe入口。请求受理/写应答不代表闭环完成。

| 内部阶段 | 现state投影 | 必需字段语义 |
| --- | --- | --- |
| 本次运动观察 | observing或pending | 原完成判据仍成立，未完成不得清请求 |
| 已完成，等待PLC清反馈 | observing | plcCompleted=true，cleared=false；reason说明正在等哪项反馈清0；保存原completionEvidence |
| 闭环已确认 | completed | plcCompleted=true，cleared=true；清写及全0新样本证据齐备 |
| 无启动的沿用位置 | completed | reusedPosition=true；cleared=true仅表示本请求无待清义务，必须引用先前有效闭环和本次复核，不冒充新清写或运动 |
| 清零超时/失效 | timeout、failed或interrupted | 已有plcCompleted事实保留，cleared=false；clearError/reason说明具体阻断，不推进recipe |
| 显式人工撤请求 | 原非成功终态；确认清零后可cancelled | cleared仅在实际全0证明后true；reason明确“人工清请求，不代表动作完成”，未知义务保留 |

可增加`handshakePhase`、`connectionGeneration`、`clearWriteResponded`、`feedbackClearConfirmed`、`clearEvidenceRef`等可选诊断字段。旧UI只识别state/reason仍能显示观察/错误，不需要页面实现变化。当前“启动清零已读回”只能在完整证明后显示，不得提前置cleared；如后续改文案或控件，先有独立前端规格。

recipe只在完成并满足清零义务后推进；XY/单轴/reuse的最终复核统一调用App证据判断，不能仍要求到位1或只读last_targets。等待期间不是recipe失败，也不是完成。

## TC-02 统一写入口与串行执行

- 纯采集仅读/发布样本，不调用轴观察或recipe。worker每轮采集→心跳→观察→recipe，必要即时读取也只用纯采集，防止poll嵌套推进。
- 沿现asyncio锁保护整笔通信和BOOL RMW。清零为跨轮次状态，等待下一采样时不持锁阻塞worker/心跳。清写一次，后续只观察。
- 连接代次与读/写实际单调水位分别记录；全局fresh或墙钟receivedEpoch不能独立证明HC-03。断线/重连立即失效旧资格，不从进程session继承。
- `/api/write`写目标/运动请求也经同一资源守卫。新非零请求须资源空闲、当前请求/反馈合规；未清、未知或已有recipe所有权时拒绝。原始手工动作缺少托管动作关联时保留“未确认”义务，不生成闭环成功或复用记录；只有可关联本次完成及合法父周期，才允许相应1→2中间转换。不能以改走raw入口绕过axis/recipe限制。
- 对坐标/目标或其他可能改变该轴状态的手工写，失效相应复用资格；关联的同周期目标准备例外按实际动作身份维护。系统复位等已观察操作使相关资格失效，不定义新自动恢复流程。
- `/api/clear`沿现显式人工操作规则撤请求，跟踪新反馈全0；不会自动清其他资源、推进recipe或解除结果未知义务。已有动作完成但清零失败、interrupted等状态也不能漏过资源守卫。

## TC-04 诊断与失败输出

复用原events.jsonl及现正式诊断，不建第二日志平台。清写应答、等待清零、全0确认、复用、阻断分别记事件，关联operationId/actionId/recipeRunId（适用）、连接代次、资源/周期、原始请求与反馈、逐字段读取水位/质量、deadline与实际处置。读未发生不填伪造时刻。

错误须说明是“PC撤请求写入未确认”“PLC旧反馈未清零”“反馈过期/断线”或“复用资格失效”，不能统一成运动未到位。延迟期间无后继派发；失败后不自动重发。新验证另记录源码版本、配置及测试来源，不覆盖1.1.4/1.1.6历史结论。

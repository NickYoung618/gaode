# 正式配方制作与真实 PLC 联调部署（2026-10-07）

目标：在独立目录交付正式 backend/frontend/desktop，现场连接参数由配置读取；不以独立 PLC 工具替代正式业务程序。

交付两个明确入口：离线配方制作（显式 FullSimulation，不构成硬件验收）和真实 PLC 联调（Production/Real，启动前只做离线协议检查）。后者不允许缺协议时退回虚拟地址。当前现场映射只作为已有联调记录的来源，机械参数与未定义信号不编造。

实施范围：恢复只读迁移归档中的原前端图片；增加调用现有存储/配方/协议 API 的部署准备工具；增加发布、启动和正常停止脚本；允许已显式配置的受控页面来源用于完整 Host 的离线制作和本机真实 PLC 联调。沿用现有 TestAllowedOrigin 配置和校验，不增加业务或 PLC 协议接口，不修改客户页面。

初始库只在显式准备命令中创建，不覆盖已有数据库。配方制作源保持未审批草稿，只为编辑器提供现有来源，不能作为现场坐标或生产执行许可。后台和 UI 的模式独立记录：本地 UI 仍使用既有 Test 令牌机制，不宣称生产账号体系。

核心验证：离线协议检查；Release 发布；正式 HTTP 配方目录、读取、校验、保存、新进程重读；桌面加载和页面资源检查；受控 Origin 预检。打包期间不连接真实 PLC、不启动真实相机、不发送运动命令。缺信号、类型或报警定义时输出原始拒绝原因并阻止真实入口。

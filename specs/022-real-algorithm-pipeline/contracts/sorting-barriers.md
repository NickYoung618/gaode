# C022-SRT：物理对象结果屏障与安全映射

依据FR-010、Q2=B及008/011/014有效处置规则。022不改变目标点、机械顺序、槽号、抓手、取放许可、在途保存及完整周期。

AwaitObjectDecision必须按冻结计划推导当前物理搬运对象完整必检集合，包括各适用阶段/面/坐标轮单图、所需融合、E绑定/原缺码处置及RequiredForOk；保存判定证据后才可消费。独立件只用自身结果；问题成员不扩大整组搬运；装配整体需全部相关部位；NG不使必要结果可省略。合法姿态退出使用原PosePending证据和原槽关联，已正式跳过检测不造结果。

RecipeSortingMapper新增对象级映射入口，输入是对象判定证据、该对象冻结SortUnit/Scope及观察参与证据，保PlanRevision/位置/classification/物理槽/排除证据验证。现MapAsync的整段Completed含义不弱化；正式对象管线不得向该入口传子集假Completed。MappingOperationId/动作OperationId按原规则关联，重复结果不生成重复分拣。普通全盘生产完成后按原序消费，当前对象未决不能跳拣；特殊本件完整识别后直接本件映射/分拣，安全位后下一件。

A阶段保现有检测整体完成→批次映射/原分拣，及特殊本件完整检测后处置的原执行链。以下对象级部分结果映射/增量预约专属C，延期而非删除；A仍逐项验证必需结果/必要保存/可靠释放及原分拣、Final屏障。

## 保留全盘目标与容量前置

当前ThreeStageWorkflowExecutor在第一分拣前冻结全部同盘目标/抓手，SortingTargetAllocator检查源占用、目标重复、NG/Pending总容量和先前预留。对象级判定不能绕过这些条件。

1. ProductionEnded及当前观察成立后，先冻结全部原序对象适用的已配置目标候选、抓手及原槽；配置有效性/占用/重复/潜在共享点核查先于首个分拣动作。特殊scope保其原上料占用证据；不得发明替代目标。
2. 可由冻结配置及已保存占用证明各可能处置分支都满足原批次安全和容量时，形成SortingSafetyEvidence；当前对象齐备后可独立预约/分拣，不等无关对象推理。
3. 若配置共享目标或NG/Pending容量须由多个对象结果共同决定，相关结果是实际共享资源依赖。先取得证明原批次可执行所必需的判定集合，再允许首个分拣；不因局部当前件结果齐备绕过原全量拒绝条件。没有共享依赖的对象不加入该集合。
4. 如无法证明增量预约与原批次准入等价，该具体配置的对象级分拣改造保持局部受限，登记现有容量/目标规则与所缺证据；不放宽配置、不自动换槽、不默许先搬后失败。该约束不阻断采集/计算重叠、当前特殊scope或安全独立目标路线。
5. 当前对象结果已保存且安全证据有效后，唯一SortingReservation记录先可靠保存。累计预留/占用、NG/Pending计数和候选使用在同Run提交边界原子核验，重入不得重复占位。取料完成提交回执仍决定放料许可，保存未知保持原资源。
6. 所有对象所需目标及capacity安全前置均满足且原序动作完成后，保留Sorting/Unload及整盘完成证据规则。Detection真Completed可晚于对象分拣，但最终完成矩阵不接受生产结束代替结果/资源完成。

这是对既有全盘安全前置的直接衔接设计，不能以“异步”删除该门禁。后续任务需把实际冻结配方是否有共享点/不足容量作为一次定向设计核查，不扩大为全场景异常矩阵。

## T041 A最终消费者

WholeTrayCompletionStore在首次Final提交以及ReconcileFinalAsync释放任务前，核本Run每Call最新持久pipeline/1生命周期；任一未Reclaimed则以AlgorithmResourcesUnconfirmed拒绝，不提交新Final/Completed或释放CommandRegistry。原允许取盘、人工确认、来源矩阵与机械条件不弱化；仅有历史Final也不能绕过未回收核对。此核查不受Run业务终态过滤、不使用无关Run资源作为屏障。公共成功返回须可靠输入/执行结束并刷新资源保存，使正常原同步链无需额外编排。

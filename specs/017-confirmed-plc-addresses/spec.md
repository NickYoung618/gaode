# 017 确定版 PLC 地址合入

日期：2026-10-06。依据：用户“这是确定的地址，现在能不能先合入再进行迁移？”及本次 PC.xls、PLC(2).xls。

本轮目标是把确定的地址、类型和已给出的反馈含义合入当前工程及现场联调工具，迁移时携带可执行的同一版本配置。正式 PLC、相机、算法的剩余接入工作仍按用户决定在中控机解决。本轮不是生产硬件验收，不扩大页面或业务流程。

## 确定事实

- PC.xls SHA256：37095748a61574d9a1c9bf17ad0ac9118d554fa73ac8f5e10003718b6627511d，26 个信号，与上一版一致。
- PLC(2).xls SHA256：8e846d0f71351f87b42db1bf40790f40766a392fd0a9e0968201f8c2056eb476，59 个信号，新增 PC_Alarm MB6037，心跳为 MB6038；INT 从 MB6040 开始，Grab_Active_ID MB6062；REAL 仍从 MB6064 开始。
- PC 心跳 MB2011；六轴启动为 BOOL 字节。BOOL 占一个字节，INT 两字节，REAL 四字节。MB6039 为未声明填充字节，不新增信号。

## 本轮要求

1. 原 XLS 按字节归档，生成 85 项共享点表，保留原名称、注释、地址、类型及来源行号。
2. 正式协议项目提供确定点表读取、MB 到可配置零基 PDU 的换算及 BOOL 字节编解码。原虚拟地址图继续作为 Test 图，不将其当现场地址。
3. 正式 PlcPoint/读取计划/信号访问器支持同字相邻 BOOL 字节，写入保留邻字节，并由同一设备的两个连接共享写协调。
4. Host 增加显式现场 Profile 配置入口。只投影含义明确的既有 SignalId；缺少的旧业务信号、型号编码、报警解释不得伪造。正式准入继续报告不完整，不能通过删校验实现假接入。
5. 联调工具默认模板更新为 85 项，补齐 R 轴已有目标、启动、到位和实际角度，保留手动填写坐标/范围/容差。旧 Field 配置在连接前给出地址版本不匹配错误，不能静默沿用旧心跳。
6. 独立验证原件与点表一致、字节读写和并发邻居保护、真实回环 TCP 的心跳/目标下发/本次运动反馈/清零及 TX/RX 记录。运行全部直接受影响的必要现有验证；不重跑无关整机历史场景。
7. 发布新版联调工具、更新迁移交接和变更清单，保留旧证据及旧发布 ZIP。

## 留到现场的事项

IP、端口、站号、两个块的 PDU 起点、PLC 反馈功能码、BOOL 字节顺序和 REAL 字序仍没有在 XLS 中定义。现场机械参数、型号 REAL 对字母的编码、缺失的 ManualZone/Teach 信号及报警解释、启动/恢复流程冲突需在对应业务工作中处理。不得把“内存地址已确认”标为“线协议和整机已验收”。

## 同轮用户补充及并行分工

用户要求中控机并行改进易懂的联调界面，只填 IP/端口即可查看交互，不受额外确认字段限制。本轮给出独立目录开发提示词；主工程合入不等待该界面完成。

本地0.4地址基线同时取消只读连接的 Mapping.Confirmed/来源非空门槛，给 UnitId=1、PC/PLC PDU base=1000/3000、EvenLow、Abcd 的可修改初值，并记录“未校准”。这些初值不是现场事实。新版地址身份校验防止继续写旧旋转/心跳地址。首页简化、动作配置门槛精简及完整新界面由中控机独立包继续实施；本地0.4不据此宣称这些界面工作已完成。

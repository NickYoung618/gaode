三、已确认的业务流程

1. 设备公共位置

整台设备共享两种位置：
- 人工上／下料位：上料和下料共用一份坐标。
- 3D检测位。

公共位置不在每份零件配方中重复配置，不新增“每配方上料点、下料点”。
沿现有公共配置能力实现真实保存、完整读取及运行快照；已启动料盘不得被后续修改中途换坐标。

保留原有F定位及其他仍有效配置，不因这份文档只列两个公共位置就删除它们。

示教采用最小范围：
- 从现有设备语义接口读取当前可靠实测位置；
- 操作者确认后保存到对应公共位置；
- 显示已保存值和实际保存结果。
坐标轴和约束沿当前已确认固定点、运动及机械合同，不凭空扩轴、补范围或造零值。
没有可靠实测时明确不可示教，不把目标值、缓存旧值或模拟值称为真实设备位置。
不新增点动平台、任意寄存器编辑、自动试跑或其他高级功能。

2. 人工上料与启动

人工放入料盘并点击启动后：
检查PLC通信、自动模式、故障及人工区域占用
→ 上位机发送就绪
→ 等待PLC_Ready_State=1
→ 移动到3D检测位
→ 核本次到位反馈及实际坐标
→ 3D采集和算法处理。

PLC_Ready_State=1的本次业务含义已经确认：料盘夹紧，允许移动。
不能在发送上位机就绪前错误要求必须已经收到该后续反馈，形成相互等待。
业务层只消费语义就绪能力，协议字段、地址、编码留在通信层。

人工已在上下料位放盘，启动时不增加无依据的重复上料移动。

3. 3D占用、姿态与位置身份

- 有料且姿态正常：参与检测。
- 无料：跳过该位置，不检测、不抓取、不分拣。
- 有料且姿态异常：跳过检测，最后分拣到Pending区。
- 3D不提供或修正抓取坐标。

最新确认表示无料空位本身不能被推断为“本应有料却缺件”。不得把未选格、NG/Pending空格或上一盘的位置当成本盘缺件。
本轮不另造“预计必须有料”的规则；同步澄清来源旧“缺件告警”在现有占用口径下的适用边界。

F绑定前，使用本次3D提供的真实位置身份、行列或已有明确设备级映射；不能提前假装已有本盘配方，不能借上一盘配方，也不能编造物理号→行列公式。
F绑定后，与冻结配方的CellId、区域、成员和坐标关联。实际有料位置若不能合法匹配配方，沿现有准入拒绝，不悄悄漏检。

有效空盘结果必须与采集失败、算法失败、结果缺失、Unknown或覆盖不完整区分。
正式设备映射缺失如实限制对应能力；软件验证允许使用明确声明的受控适配器和完整映射输入，但不得冒充现场资料。

布局保留实际格子、空位、区域号和稳定身份，不因跳过空穴重新编号。
成组的每个零件有独立检测位置；保留组关系，不把一个组全部成员当作同一物理穴位。
半成品的检测部位不擅自改成多个独立可搬运零件。

4. 异常提示与决策

本次检查发现姿态异常时：
- 弹窗列出行、列、异常类型和原因。
- 只有“人工介入”“继续”两个业务操作。
- 10秒倒计时，超时默认继续。

前端只显示和提交选择，后端持有本次决策身份、原始截止时间和最终选择：
- 继续、人工介入、超时只能形成一个有效结果。
- 刷新页面不能重开10秒。
- 不得两个分支都执行或重复推进。
- 选择人工介入后停止倒计时。
- 停止、取消、故障不能被超时默认继续重新放行。
- 选择及自动继续须有可关联、可持久的真实记录。

首次继续后进入F扫码及配方绑定。
后续翻面放回复查按同一规则处置，使用本盘已有冻结配方，不重新扫码、更换配方或重复执行已完成步骤。
同一穴位重复观察不得生成重复Pending搬运。

新增10秒选择窗口单独表达，不扩大原I/O、动作、保存、取消期限。正确安排其与检测阶段预算的关系，不能隐藏等待或每次复查重开整段业务期限；需要的实际工作量承接先落实合同，不凭空新增时间预算。

5. 人工介入

首次检查后人工介入：
跳过F扫码、检测、分拣
→ 公共下料
→ 人工取盘确认
→ 本盘结束。

后续复查选择人工介入：
保留已发生的真实事实，跳过尚未执行的后续扫码、检测和分拣
→ 复用同一公共下料
→ 人工取盘确认
→ 以提前结束原因结束本盘。
不得倒改已完成事实，也不得显示全部零件检测完成。

6. 空盘

全部待检位置均无料：
提示“料盘为空”
→ 跳过后续扫码、检测、分拣
→ 公共下料
→ 人工取盘确认
→ 本盘结束。

全部有料但姿态异常不等于空盘，仍按异常选择处理；继续后需要实际Pending分拣。

7. 姿态异常件Pending分拣

使用配方取件坐标及Pending放料坐标，复用公共分拣、实际抓取反馈、取料提交门、放料反馈和既有必要安全事实。
记录为：
- 检测状态：未检测；
- 结果归类：Pending；
- 原因：3D姿态异常；
- 物理处置：按实际进度记录，完成反馈及保存成立后才记已分拣。

不伪造相机或算法检测结果，不写成OK。
后续复查异常时保留已完成检测的原始证据，另外记录后续检测终止和姿态异常Pending处置，不能抹掉曾经真实执行的检测。

Pending容量、目标关联或必要抓取条件不满足时沿既有明确拒绝规则，不新增临时落点、自动回退OK、盲抓或假完成。

普通配方保留原检测和分拣节奏。
014特殊正常件保持逐件上工位、旋转拍照、处置、安全返回；本次姿态异常件不进入旋转检测，按新规则在最后从本件原槽分拣到Pending。
抓手沿已有合法配置及通信能力，不新增协议字段或默认选择。

8. 公共下料

人工介入、空盘、正常完成共用：
移动到人工上／下料位
→ 核本次到位和实际坐标
→ 按已有合法条件允许人工取盘
→ 接收人工确认
→ 保存本盘结束事实。

提前结束允许尚未F绑定、尚无配方、尚无检测和分拣事实。
必须在共同业务层补齐合法的提前结束路径，不能伪造配方、检测完成、算法事实或分拣完成来满足旧模型。

“本盘已结束”与“全部零件检测完成”分别表达。
保存正常完成、人工介入、空盘等真实结束原因。
人工取盘确认后位置已是上料位，不再次移动，下一盘通过新的启动和新的运行身份进入。

不得从“就绪表示夹紧”推导未提供的松夹信号，不新增虚构PLC解锁握手。

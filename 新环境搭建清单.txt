一、需要准备的软件

1. Windows x64 桌面环境
   完整前端使用 WPF + WebView2，需要可登录的 Windows 桌面。
   新机器可采用 Windows 11 x64；本清单不用于 Linux 容器或无桌面的服务器部署。
   源码目录、运行数据目录及 WebView2 用户数据目录应允许当前用户读写。

2. .NET SDK 10.0.401，Windows x64，必须精确匹配
   global.json 指定 version=10.0.401、rollForward=disable。
   仅安装其他 .NET 10 SDK 或 .NET 8/9 SDK 不能满足当前源码构建要求。
   当前机器还安装了以下三个运行时，版本均为 10.0.12：
   - Microsoft.NETCore.App
   - Microsoft.AspNetCore.App
   - Microsoft.WindowsDesktop.App
   官方 Windows SDK 安装包包含上述运行时；安装后实际检查，缺少哪项再补装。
   精确重现当前运行基线时使用 10.0.12；其他补丁版本需另行验证并记录。
   不需要为了本项目先安装完整 Visual Studio 或额外 .NET workloads。
   官方下载：https://dotnet.microsoft.com/en-us/download/dotnet/10.0

3. PowerShell 7.4 或以上，Windows x64
   命令名称必须是 pwsh。Windows 自带的 Windows PowerShell 5.1 不能替代。
   当前机器版本：7.6.6；部分启动脚本明确要求最低 7.4。
   官方安装说明：https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows

4. Node.js 24 LTS x64 + npm（源码构建需要）
   当前机器：Node.js 24.19.0、npm 11.17.0，可作为复现参考。
   项目未精确锁定 Node/npm；采用 24.x LTS 并至少达到 24.12，覆盖当前锁文件依赖要求。
   使用 npm ci 还原 frontend/package-lock.json，不使用 npm update。
   不需要全局安装 TypeScript、Vite、Tailwind，也没有必须使用 pnpm/yarn 的要求。
   官方下载：https://nodejs.org/en/download

5. Python 3 x64
   当前机器：Python 3.12.10；可用该版本复现现有虚拟算法环境。
   项目没有统一 Python 版本锁文件，替换版本后应验证脚本兼容性。
   确保 python 命令能运行真实解释器，不能只存在 py 命令或商店占位入口。
   scripts/virtual-station01-algorithm.py 仅使用 Python 标准库。
   当前虚拟联调无需另装 OpenCV、PyTorch、CUDA 或相机 SDK。
   Python 自带 sqlite3 可用于数据检查，不需要安装名为 sqlite3 的 pip 包。
   复现版本下载：https://www.python.org/downloads/release/python-31210/

6. Microsoft Edge WebView2 Runtime，x64
   桌面前端运行必需。检查实际 Runtime，不能只凭安装了 Edge 浏览器判断完成。
   可使用官方 Evergreen 安装器；离线机器准备 Evergreen Standalone Installer x64。
   Microsoft.Web.WebView2 NuGet 包 1.0.2903.40 是项目 SDK 依赖，不能替代系统 Runtime。
   官方下载：https://developer.microsoft.com/en-us/microsoft-edge/webview2/
   分发说明：https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution

7. Git for Windows（拉取源码、继续开发时需要）
   当前机器 Git 版本：2.55.0.windows.4；项目没有精确版本要求。
   2026-10-06 更新：迁移包内源码带 .git，主仓库为 https://github.com/NickYoung618/gaode.git。
   首个迁移标签 migration-20261006；不要重新 git init 或删除已有历史，操作见根目录“迁移与版本回退.txt”。
   官方下载：https://git-scm.com/downloads/win

二、项目自身依赖与网络

1. 后端、VirtualPlc、桌面端依赖通过 dotnet restore/build 还原。
   后端集中版本定义：backend/Directory.Packages.props。
   当前关键版本：EF Core SQLite 10.0.12；目标框架为 net10.0。
   桌面目标框架：net10.0-windows10.0.17763.0。
   保留各项目 packages.lock.json，不擅自升级 NuGet 依赖。

2. 前端通过 npm ci 还原。
   当前主要依赖：TypeScript 5.9.2、Vite 7.1.5、Tailwind CSS 3.4.17、
   lucide 0.468.0、@microsoft/signalr 8.0.7；以 package-lock.json 为准。
   前端构建产物由桌面 WebView2 加载，不需要单独安装 Nginx 或 IIS。

3. 当前业务数据库是 SQLite 文件，不需要 MySQL、SQL Server、PostgreSQL 或 Redis 服务。
   SQLite 依赖随 NuGet/应用还原，不需要单独安装数据库服务器。
   新 Test 数据库由 backend/tools/Gaode.StorePrep 创建并执行迁移。
   不要手工创建空 db 文件、直接复制正在运行的旧库，或让正常 Host 强行修改旧库结构。

4. 在线安装/还原需能访问官方软件下载站、NuGet 和 npm 包源及其下载地址。
   默认包源包括 https://api.nuget.org/v3/index.json 和 https://registry.npmjs.org/。
   离线部署须提前准备安装包、对应锁文件需要的 NuGet/npm 包缓存，或完整发布包。
   当前虚拟算法无需额外 pip 下载；完整开发工作流的依赖见第六节。

四、端口、目录与后续启动约定

本机虚拟联调默认端口：
  127.0.0.1:5001   Host HTTP API；SignalR 为 /hubs/station01
  127.0.0.1:5080   VirtualPlc 监控页及 HTTP API
  127.0.0.1:1502   VirtualPlc Modbus TCP，默认 Unit ID=1
  Python worker   由 Host 启动管理，经标准输入/输出通信，无需额外监听端口

检查端口是否被占用；有冲突时使用启动脚本的端口参数，不结束无关进程。
本机联调使用回环地址，不需要向局域网或公网开放这些端口。
后续前端 API/SignalR 地址应由启动脚本注入，保证 HTTP/HTTPS 与 Host 一致。

源码联调入口：scripts/start-station01-virtual-loop.ps1。
该脚本默认使用 Debug Host、Debug VirtualPlc、Debug StorePrep、Release 桌面端。
它需要 GAODE_TEST_OPERATOR_TOKEN 或 -OperatorToken；本地测试令牌按会话准备，不写入交接报告。
008 用例使用 -FixtureManifest 指定现有、匹配的用例清单。
清单中的 configRoot、recipeCatalogPath、imageManifestPath、workerManifestPath、
workerScriptPath 要解析为新机器上存在的绝对路径，并保持对应摘要一致。
仅为迁移路径调整生成的部署配置，不修改来源规格、配方业务含义或原型。
008 运行目录受限于项目 artifacts/recipe-execution-008 下；007 默认目录位于 artifacts/station01-007 下。
每次使用独立的新 TestRoot，保留 SQLite、媒体、process.json 和 logs。

当前文本只要求运行前检查。环境安装完成不等于主流程通过；后续联调按选定用例单独验证。
真实 PLC、相机、算法部署还需要实际设备网络参数、厂商 SDK/驱动、模型及生产配方。
这些生产输入应来自现场确认，本清单不推定品牌、版本、PLC 信号或 CUDA 要求。

五、安装后的最小验收

在 PowerShell 7 终端中执行，先将 $projectRoot 替换为新机器的实际目录。
每一步失败就保留错误并处理，不继续宣称构建成功。

  $ErrorActionPreference = 'Stop'
  $PSNativeCommandUseErrorActionPreference = $true
  $projectRoot = 'E:\dzk\gaode-1'
  Set-Location -LiteralPath $projectRoot
  Get-Command dotnet,pwsh,node,npm,python
  dotnet --version
  dotnet --list-runtimes
  pwsh -NoProfile -Command '$PSVersionTable.PSVersion.ToString()'
  node --version
  npm --version
  python --version
  python -c "import sys,sqlite3,json,hashlib; print(sys.executable); print(sqlite3.sqlite_version)"

必须确认项目目录内 dotnet --version 为 10.0.401，三个 .NET 运行时均存在。
确认系统已装 WebView2 Runtime；只检查 NuGet 包或 Edge 浏览器不算通过。

还原并编译，顺序如下（这些操作会生成正常构建产物）：

  dotnet restore backend/Gaode.slnx --locked-mode
  dotnet build backend/Gaode.slnx -c Debug --no-restore
  dotnet restore VirtualPlc/VirtualPlc.csproj --locked-mode
  dotnet build VirtualPlc/VirtualPlc.csproj -c Debug --no-restore
  dotnet restore backend/tools/Gaode.StorePrep/Gaode.StorePrep.csproj --locked-mode
  dotnet build backend/tools/Gaode.StorePrep/Gaode.StorePrep.csproj -c Debug --no-restore
  Push-Location frontend
  try {
      npm ci
      npm run typecheck
      npm run build
  } finally {
      Pop-Location
  }
  dotnet build desktop/Gaode.Station01.Desktop.csproj -c Release

有原型归档时，替换真实路径后追加：

  pwsh -NoProfile -File frontend/scripts/verify-prototype.ps1 -Archive 'E:\dzk\gaode\原型.zip'

确认 frontend/dist 中存在 login.html、a.html、data-view.html、assets、vendor、runtime.js。
确认桌面 Release 输出中已复制 frontend/dist，以及 Host、VirtualPlc、StorePrep 编译成功。
环境准备阶段不要求跑全部历史用例，不将仅编译通过写成业务联调通过。

仅运行完整发布包时：
  必需：Windows x64 桌面、PowerShell 7.4+、Python、WebView2 Runtime，
        .NET 10 x64 的 ASP.NET Core Runtime 和 .NET Desktop Runtime。
  安装后同样检查 NETCore/App、AspNetCore/App、WindowsDesktop/App 三类运行时。

  packaging 下的打包源目录或单独覆盖文件不是完整发布包。
  历史包、当前源码与正在设计的功能版本可能不同；以实际包清单及验收范围为准。

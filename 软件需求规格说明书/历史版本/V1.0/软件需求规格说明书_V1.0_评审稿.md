## 1 编制约定

### 1.1 目的、对象与边界

用于制冷机密封零件缺陷智能检测设备的软件需求评审、开发、联调、测试、交付及维护。服务对象为1套主体设备及其上位机软件、视觉算法、离线训练工具、PLC协同、数据追溯与MES接口。原文中的“X零件”按当前项目名称统一表述为制冷机零件；未经确认的产品名称不做强制同义合并。

软件需求覆盖所有现有资料中可识别的功能与约束。机械强度、整机供电/气源、机构定位精度、硬件安全回路等保留为外部依赖和联合验证事项。软件不独立保证机构物理性能；但必须实现已明确的安全互锁、到位确认、异常锁定与追溯。

## 4 业务流程与状态约束

### 4.1 标准生产流程

1. 登录并完成自检；核对未完成任务和当前设备物理状态，满足就绪条件。

2. 输入工单/批次与场景，人工上料；点击软件开始，PLC安全检查通过后等待实体按钮。

3. 实体启动后PLC夹紧料盘并反馈，移动至初始识别工位；PC执行3D和料盘码识别，检查有无/姿态并绑定身份。

4. 自动唯一匹配配方，验证型号/场景/检测面、模型、坐标与容量，完成区域配置握手并生成整盘任务。初始扫描与配置顺序依OPEN-09最终冻结。

5. 普通零件按当前物理面进行相机组批采并逐件融合；需要翻面时执行翻面闭环，核验实际面，重扫3D，必要时扫码，再执行后续必检面。

6. 特殊零件按类型取至旋转工位、旋转到位、相机组采集融合，判定后直接回原位/NG/待定区，闭环完成当前件。

7. 核对每件必检项目完整性，汇总OK/NG/Pending；生成尚未完成的普通件分拣任务，执行取放料与可靠完成反馈。

8. 本地保存单件/整盘检测和分拣记录；移动至下料位并解锁，提示取盘及下料确认；MES异步上传/补传，回执状态独立管理。

本节为整合后的逻辑顺序，不能用于掩盖原资料顺序冲突。OPEN-04、OPEN-06、OPEN-09未关闭前，运动调度及PLC接口仍须评审；已明确的安全、身份和数据完整性门禁始终适用。

### 4.2 软件状态与迁移

| 状态 | 允许行为/进入条件 | 退出条件/禁止事项 |
| --- | --- | --- |
| 自检 | 检查设备连接、存储、模型/配方、版本、许可、任务恢复和PLC物理状态。 | 自检通过进入就绪；失败进入报警；不得直接生产运动。 |
| 待机 | 无活动生产任务，可查看历史、建立工单；保持监控和心跳。 | 完成初始化与就绪校验后进入就绪。 |
| 就绪/待实体启动 | 软件就绪、安全条件满足，发起启动请求并等待实体启动。 | 实体按钮与夹紧确认后进入运行；就绪不等于自动动作已授权。 |
| 运行 | 按已冻结任务执行采集、算法、翻面、旋转和分拣。 | 暂停/取消/故障转入相应受控状态；不可热改在途判定基线。 |
| 暂停 | 保留任务及在途动作状态，只允许批准的查看/恢复/处置。 | 检查原因已消除及物理状态后恢复；不自动跳过当前件。 |
| 报警 | 显示故障，阻断受影响动作，保存证据；可有多个并发故障。 | 消除原因并确认恢复条件；消音/确认不等于允许启动。 |
| 安全停机 | PLC执行安全动作，PC锁定新生产指令。 | 人工复位、现场确认及互锁复查后才可恢复。 |
| 人工复核 | 对Pending或未知状态进行身份、图像、结论和实物处置核对。 | 保存审计及物理去向；是否与其它任务并行须验证隔离。 |
| 维护/示教 | 授权人员进行设备诊断和坐标示教；自动运行停止。 | 退出后重新就绪检查；维护入口不能绕过硬件安全。 |

任务状态、设备状态、结果状态、分拣状态与MES状态应分开存储。例如“检测NG、分拣待确认、MES待传”是合法可诊断组合，不能简化为一个“完成”布尔值。此为实现SRC-01事务一致性要求的派生数据约束。

### 4.3 判定与动作门禁

| 条件 | 允许结论/行为 | 禁止行为 |
| --- | --- | --- |
| 必检面、相机、项目齐全且结果有效合格 | 输出OK，按配方保留原位或进入OK去向。 | 只凭部分相机/部分面合格输出OK。 |
| 至少一项已确认NG，其余均有效 | 输出NG，记录缺陷及目标NG区域。 | 融合为OK。 |
| 存在不确定项、缺面、算法超时、无效测量 | Pending或锁定；具体路径由批准规则决定。 | 把技术失败直接当作合格。 |
| 同时有确认NG和Pending/无效项 | 禁止OK，保存所有原因；最终NG/Pending优先级待确认。 | 无依据丢弃未确定项。 |
| 空槽/缺件 | 记录空位/缺件并按任务允许规则跳过。 | 计入已检OK或掩盖应有件丢失。 |
| 身份/配方冲突，坐标无效，安全不满足 | 锁定受影响流程并报警。 | 仅标Pending后仍发送不安全运动。 |
| 命令已发但未获匹配完成反馈 | 保留执行中/待确认，超时受控恢复。 | 标为已分拣或自动重发不可判定的动作。 |
| MES断线、本地存储可靠 | 继续本地生产并缓存/告警。 | 丢弃记录或虚标MES上传成功。 |

### 6.1 提议的文件目录规范

以下为派生建议，最终以批准的命名规范为准：数据根目录 / 日期 / 批次 / Task_ID / Pallet_ID / Part_ID / Attempt_ID / Face_ID / Camera_ID。每层应处理非法字符、重复码及路径长度；使用原始标识与安全目录名的映射避免信息丢失。原始数据、标注结果、报告、日志、模型和备份分目录保存。

### 7.2 PLC数据规则与握手

Coil原标记为0x；Holding Register原标记为4x。下表逐项保留原地址写法，不直接换算为报文偏移，不推断4x后缀十六进制/十进制约定。Float32占连续2个16位寄存器，必须确认字与字节排列。寄存器上的Bool（4x0027、4x0028）按何种编码及读写方式使用需确认。0/1约定适用于二态点，不能覆盖各Int16状态枚举。

## 9 性能与质量验收口径

| 指标 | 原始要求 | 统计/验收约束 |
| --- | --- | --- |
| 最小可识别点 | 0.01mm | 实物边界样本验证；不能用理论亚像素换算替代。 |
| 凹坑 / 划伤 | 直径≥0.1mm NG / 长度≥0.2mm NG | 包含等号，样件阈值上下边界均验证。 |
| OK/NG准确性 | 相对批准真值均100% | 指批准适用范围与独立盲测集的验收目标，不宣称对未知缺陷无限泛化。 |
| Pending / 自动明确判定 | ≤2% / ≥98% | 原始算法Pending单列，不能用人工复核后的OK反向降低原始Pending率。 |
| 单密封面完整周期 | ≤10s/面 | 含定位、采集、算法及记录/报告；均值、P95、最大值和超限明细均报告。 |
| 最大换型 / 辅助时间 | ≤0.25h / ≤0.1h每托盘 | 起止、人工工作和首件边界需确认。 |
| 可用率 / 稳定性 | ≥95% / 连续7×24h | 按批准运行时间/停机分类统计，不擅自扣除故障。 |
| 轮询 / 扫描 / 心跳 | PC≤50ms / PLC≤10ms / 断联3s | 负载下实测；轮询周期不等于所有业务响应时延。 |
| 动作超时 | 不执行模拟下2s内报警 | 取自PLC验收1，不任意泛化为所有长行程动作必须2s完成。 |
| 运动重复定位 | ±0.005mm 与 ±0.01mm@3σ存在冲突 | OPEN-17确认后单独做机械计量验证。 |

建议统计集合：N为批准盲测中应检有效工件数；N_OK、N_NG、N_P为原始最终三态输出数；另列技术失败/未完成数N_E，核对N=N_OK+N_NG+N_P+N_E。Pending率=N_P/N，明确判定覆盖率=(N_OK+N_NG)/N；错误放行是“真值NG但输出OK”，错误拒收是“真值OK但输出NG”。OK判定正确率和NG判定正确率分别以输出OK/NG的样本为分母；真值分类召回与漏检另算。分母为0时报告不适用，不能记作100%。上述公式为评审建议，需与真值分类及异常处理规则一起批准。

失败/缺面工件不得从验收分母静默删除，Pending不得计入OK；漏检还应同时检查物理工件、检测面、ROI、触发数、图像数与结果数完整性。对新增缺陷、型号、光照/表面变化和模型变更，应重新评估覆盖范围与回归样本。
